# Fluxo de trabalho

Projeto experimental pessoal. Documentação em português, identificadores e código em inglês.

- `main`: documentação/código estável.
- `develop`: integração contínua das próximas etapas.
- `feature/<assunto>`: features; `spike/<assunto>`: experimentos técnicos.
- Mudanças por PR, com link para issue quando houver. Evitar merges de funcionalidades não testadas.
- Commits preferencialmente no padrão Conventional Commits (`docs:`, `feat:`, `fix:`, `test:`, `chore:`).
- Não versionar certificados, provisioning profiles, credenciais, contas Apple ou dados pessoais de Screen Time.
- Para testes manuais, anotar modelo iOS/dispositivo, versão do sistema, estados de permissão e passos reproduzíveis.
- Rascunhos de UX e economia de créditos devem continuar reversíveis até serem validados.
